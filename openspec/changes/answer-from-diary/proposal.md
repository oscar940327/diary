# Proposal

後續候選；先保留方向，尚未決定開始時間或實作細節。

## Why

累積的日記應能協助擁有者回顧經驗，例如根據過往紀錄準備面試。
回答必須能找回依據，不能把猜測或一般建議當成擁有者真的經歷過的事情。

## What Changes

- 提供向 Insight Agent 提問的入口，先找相關 Original Content，再產生回答。
- 對個人經歷的敘述提供可追溯的日記來源與日期。
- 區分紀錄事實、推論與一般建議；證據不足時明確說明。
- 納入免費模型額度不足、服務失敗與私人資料處理方式的規劃。

## Capabilities

### New Capabilities

- `diary-grounded-answers`：根據檢索到的日記回答問題，附上來源，並說明證據不足。

### Modified Capabilities

目前沒有既有能力規格需要修改；開始細化時重新核對已完成的能力。

## Impact

後續會涉及日記檢索、模型呼叫、回答及來源呈現。
模型服務、對話保存與來源版本處理尚未決定；不把本提案當成選定任何供應商。

## Non-goals

- 不自動修改日記、建立提醒、操作其他服務或公開私人內容。
- 不在這個 change 實作心情預測或其他分析模型。
- 不自動切到付費模型、購買額度或升級方案。

## Dependencies

- **必要前置**：`capture-diary-entry` 與可用的日記查詢、檢索能力。
- **必要前置**：開始實作前先確認可接受的模型資料處理政策與額度行為。
- **建議順序**：第 7 個，先完成 `search-diary-records` 以重用檢索；`browse-diary-by-date` 可供來源閱讀。
- **建議順序**：若 `edit-and-version-entries` 已完成，引用需能對應實際使用的原文版本；未完成時也要先決定如何保留回答依據。

## Open Questions

- 是否使用 `/ask`？第一版是一問一答還是持續多輪對話？
- 選用哪個模型服務？私人日記的保存、處理政策是否可接受？
- 免費額度不足或模型失敗時如何回覆，而日記記錄與查詢仍能使用？
- 引用哪些內容、如何查看來源，以及如何處理修改後的原文？
