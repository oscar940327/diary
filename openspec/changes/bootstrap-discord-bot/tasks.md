# Tasks

以下是這個 change 的工作清單，勾選表示已完成該項驗收；未勾選項目仍待後續執行。
依 [規格](specs/discord-command-access/spec.md) 與 [設計](design.md) 實作，不另外建立 tickets 或 ADR。

每個編號分組是一個 stage，`X.Y` 是該 stage 裡的 task。每次 apply 由使用者指定 stage 範圍，
例如「只做 Stage 1–2」；只做指定範圍，前置未完成先回報，完成後停止，不自行接續後面的 stage。
有行為變更的 task 採 Red → Green → Refactor，記錄預期失敗與通過的證據；完成驗收才勾選。

Stage 1–4 依序完成本機實作，Stage 5 另開新 session 做獨立審查，通過後才進 Stage 6 部署驗收。
Stage 6 的外部操作需有對應授權；只完成本機工作不能勾選它或宣稱已上線。
只完成 Stage 1–2 時，交付的是驗證入口與協定 `PING`／`PONG`，使用者的 `/ping` 在 Stage 3。

目前下一步：Stage 1–2 已完成提前獨立審查；使用者已接受歷史 ADR 刪除留在本 PR，範圍 finding 已解除，可指定接續 Stage 3。
比較基準與審查結果見 [目前方向的下一步](../../../DISCUSSION.md#下一步)；這次提前檢查不視為 Stage 5 完成。
