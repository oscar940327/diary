# Spec Delta

## Purpose

提供私人 Discord 日記服務的指令入口，讓擁有者在指定伺服器確認後端連通，並在加入日記功能前建立可信任的請求驗證與使用限制。這個能力也區分 Discord 自動驗證入口的請求與使用者指令，避免安全檢查妨礙正常設定。

## ADDED Requirements

### Requirement: 驗證每次 Discord 請求

系統 SHALL 在處理互動內容前，使用對應應用程式的公開金鑰驗證 Discord 簽章、時間戳記與未修改的請求本文。缺少必要簽章標頭、簽章格式錯誤或驗證失敗時，SHALL 回傳 HTTP 401，且不得執行指令或回覆成功。

#### Scenario: 有效簽章
- **WHEN** 設定完整且請求的簽章符合時間戳記與原始本文
- **THEN** 系統繼續檢查互動內容；簽章有效本身不代表使用者已獲授權

#### Scenario: 缺少或錯誤的簽章
- **WHEN** 設定完整但缺少任一必要簽章標頭，或簽章格式錯誤、金鑰不符
- **THEN** 系統回傳 HTTP 401，不產生 Discord 成功訊息

#### Scenario: 本文或時間戳記被修改
- **WHEN** 已簽署請求的本文或時間戳記被改動，但沿用原簽章
- **THEN** 系統回傳 HTTP 401，且不進入指令處理

### Requirement: 支援 Discord 入口驗證

系統 SHALL 對簽章有效、應用程式相符的 Discord 協定 `PING` 回傳 HTTP 200 與 `PONG`（回覆類型 1）。這種請求 SHALL 不要求擁有者、伺服器或頻道欄位；此例外只適用於協定驗證，不適用於 `/ping` 指令。

#### Scenario: 入口驗證不含使用者資訊
- **WHEN** 必要設定完整，Discord 傳來簽章有效且應用程式相符的協定 `PING`，未包含使用者、伺服器與頻道
- **THEN** 系統回傳 HTTP 200 與 `{"type":1}`，讓 Discord 能驗證入口

#### Scenario: 偽造入口驗證
- **WHEN** 請求宣稱是協定 `PING`，但簽章無效
- **THEN** 系統回傳 HTTP 401，不回傳 `PONG`

### Requirement: 指令僅供指定伺服器的擁有者使用

系統 SHALL 只接受指定伺服器內由指定擁有者發出的指令；兩個 ID 都必須符合環境設定，且取自已驗證簽章的互動內容。系統 SHALL 不以名稱、暱稱、角色、管理員權限或額外輸入的帳號參數取代 ID 核對。`/ping` SHALL 不綁定單一文字頻道。

對可辨識的應用程式指令，若帳號或伺服器不符、缺少可核對的使用者身分，或來自私訊，系統 SHALL 回傳 HTTP 200 與僅操作者可見的拒絕訊息，不執行指令，也不透露允許的 ID。註冊的 `/ping` SHALL 僅限指定伺服器，不註冊為全域指令。

#### Scenario: 擁有者在兩個文字頻道使用
- **WHEN** 同一擁有者分別在指定伺服器內兩個可使用指令的文字頻道發出簽章有效的 `/ping`
- **THEN** 兩次都通過授權，不因頻道 ID 不同而拒絕

#### Scenario: 其他使用者包含管理員
- **WHEN** 指定伺服器的其他使用者發出簽章有效的指令，即使擁有管理員權限
- **THEN** 系統只向該操作者顯示拒絕訊息，不執行指令

#### Scenario: 擁有者在錯誤伺服器或私訊使用
- **WHEN** 收到擁有者從其他伺服器或私訊發出的簽章有效指令
- **THEN** 系統只向操作者顯示拒絕訊息，不執行指令

#### Scenario: 無法核對操作者
- **WHEN** 已驗證簽章且可辨識為指令，但缺少可核對的操作者帳號 ID
- **THEN** 系統拒絕指令，不預設為擁有者

### Requirement: 私人連通檢查回覆

系統 SHALL 對通過簽章與授權檢查的 `/ping`，在 Discord 規定的 3 秒初次回覆期限內回傳 HTTP 200 與訊息回覆（類型 4），內容為 `Pong!`，並標記為僅操作者可見（`EPHEMERAL`）。本 change 的成功、拒絕及未支援指令訊息 SHALL 都僅操作者可見，不另發頻道訊息或儲存日記；回覆不得包含憑證或內部錯誤細節。

#### Scenario: 正常連通
- **WHEN** 擁有者在指定伺服器執行有效的 `/ping`
- **THEN** 系統在初次回覆期限內回覆 `Pong!`，只有操作者能看見，頻道不新增公開回覆

#### Scenario: 未支援的指令
- **WHEN** 通過驗證與授權的操作者發出此版本未支援的應用程式指令
- **THEN** 系統在初次回覆期限內回覆僅操作者可見的「不支援此指令」提示，不誤回 `Pong!`

### Requirement: 無效內容與缺少設定時停止處理

系統 SHALL 對已驗證簽章但無法解析的 JSON、不支援的互動類型、缺少必要互動結構或應用程式 ID 不符的請求回傳 HTTP 400，不執行指令。可辨識的指令缺少操作者或伺服器時，SHALL 依授權拒絕規則處理。

若驗證與授權所需的環境設定缺少或格式無效，系統 SHALL 回傳 HTTP 503，不使用預設擁有者、不略過驗證、不回覆成功。錯誤回應與應用程式日誌 SHALL 不包含 Bot token、互動 token、完整請求本文或內部例外堆疊。

#### Scenario: 已簽署的錯誤內容
- **WHEN** 設定完整且簽章有效，但本文是無法解析的 JSON、應用程式 ID 不符，或互動結構／類型不支援
- **THEN** 系統回傳 HTTP 400，不回覆指令成功

#### Scenario: 缺少必要設定
- **WHEN** 公開金鑰、應用程式 ID、擁有者 ID 或指定伺服器 ID 缺少或格式無效
- **THEN** 系統回傳 HTTP 503，不放寬限制，回應與日誌不洩漏憑證或原始本文

### Requirement: 測試與正式環境隔離

系統的測試與正式環境 SHALL 使用不同 Discord 應用程式、Worker 與對應設定，不共用 Bot token。更動測試入口或註冊測試指令 SHALL 不修改正式應用程式。本機自動驗收 SHALL 能使用測試用簽署金鑰完成，不依賴 Discord／Cloudflare 真實憑證，也不呼叫其遠端服務。真實憑證 SHALL 不進入版本控制。

#### Scenario: 無雲端憑證的本機驗收
- **WHEN** 開發者在沒有真實 Discord／Cloudflare 憑證的環境執行自動測試
- **THEN** 測試能用測試用金鑰驗證入口、授權與回覆情境，不連線遠端服務或建立資源

#### Scenario: 明確選擇測試環境
- **WHEN** 未來執行測試環境指令註冊或更新測試入口
- **THEN** 操作只使用該環境的應用程式、伺服器與 Worker 設定，正式環境維持原設定

#### Scenario: 註冊操作未指定環境
- **WHEN** 指令註冊操作未明確指定測試或正式環境
- **THEN** 操作停止且不發出註冊請求，不預設操作正式環境
