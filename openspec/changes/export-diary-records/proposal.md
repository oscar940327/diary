# Proposal

後續候選；先保留方向，尚未決定開始時間或實作細節。

## Why

私人日記需要能帶走，讓擁有者保留自己的副本，降低對單一平台的依賴。
先規劃可讀取的匯出，再決定備份與還原的完整做法。

## What Changes

- 提供只有擁有者能使用的匯出入口。
- 匯出保存的日記原文與理解紀錄所需的識別、時間等資料。
- 規劃私人取得匯出結果的方式，避免將紀錄送到其他人的頻道。
- 排除密鑰、登入資料與服務憑證。

## Capabilities

### New Capabilities

- `diary-record-export`：讓擁有者取得可攜帶的日記資料副本。

### Modified Capabilities

目前沒有既有能力規格需要修改；開始細化時重新核對已完成的能力。

## Impact

後續會涉及 D1 讀取、匯出內容與交付方式。
若日記版本或其他衍生資料已加入，需要一起釐清匯出的涵蓋範圍。

## Non-goals

- 不在此 change 實作匯入、資料庫還原或自動排程備份。
- 不自動同步到外部儲存，也不發布到 note-garden。
- 不新增付費儲存方案。

## Dependencies

- **必要前置**：`capture-diary-entry`，需要已有可讀取的日記資料與擁有者驗證。
- **建議順序**：第 4 個，前三個功能可日常使用後，先提供能帶走紀錄的方式。
- **建議順序**：不必等待 Agent 或版本功能；若它們先完成，需再確認是否一併匯出。

## Open Questions

- 匯出使用什麼格式？需要全部資料或日期範圍選擇？
- 是否包含訊息連結、版本歷史或未來的 Agent 對話？
- 如何交付檔案，以及處理資料量與 Discord 檔案限制？
