# Proposal

後續候選；先保留方向，尚未決定開始時間或實作細節。

## Why

擁有者可能記得內容或關鍵字，卻不記得日期。
直接搜尋能幫忙找回紀錄，也能為未來 Agent 提供可重用的日記檢索能力。

## What Changes

- 讓擁有者使用關鍵字，搭配日期條件查找日記。
- 顯示結果日期、原文片段，以及可用的閱讀或訊息連結。
- 搜尋直接回傳紀錄，無須呼叫回答生成模型。
- 搜尋範圍以自己可存取的日記為準。

## Capabilities

### New Capabilities

- `diary-record-search`：以關鍵字與日期條件找出日記，提供來源片段及閱讀位置。

### Modified Capabilities

目前沒有既有能力規格需要修改；開始細化時重新核對已完成的能力。

## Impact

後續會涉及 D1 查詢與搜尋結果呈現。
中文、英文及專有名稱的查找效果需要驗收，搜尋做法與索引尚未選定。

## Non-goals

- 不生成 Agent 回答，也不自動摘要整段歷史。
- 不預先決定向量資料庫、embedding 或複雜排序模型。
- 不搜尋 note-garden 或外部網站。

## Dependencies

- **必要前置**：`capture-diary-entry`，需要已有可檢索的原文與日期資料。
- **建議順序**：第 6 個；可重用 `browse-diary-by-date` 的閱讀方式。
- **建議順序**：若修改與版本先上線，需確認搜尋目前版本的行為；不必先完成 Agent。

## Open Questions

- 搜尋指令名稱、日期篩選與結果排序怎麼安排？
- 中文、英文與專有名稱需要哪些匹配行為？
- 結果太多、沒有結果或內容很長時如何顯示？
- 是否需要查找舊版本，或只顯示目前內容？
