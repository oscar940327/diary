# Proposal

後續候選；先保留方向，尚未決定開始時間或實作細節。

## Why

擁有者希望在需要的時間收到待辦提醒，減少只記在日記裡卻忘記執行的情況。
提醒需要持續保存及排程處理，不能只靠一次聊天回覆。

## What Changes

- 讓擁有者明確建立包含內容與時間的提醒。
- 提供查詢與取消提醒的方式。
- 保存提醒及處理狀態，並規劃到期後透過 Discord 發送訊息。
- 將排程與 Bot 指令分開處理，納入服務重啟、失敗和重複處理的情況。

## Capabilities

### New Capabilities

- `diary-reminders`：建立、查詢與取消私人提醒，並在到期時安排 Discord 訊息。

### Modified Capabilities

目前沒有既有能力規格需要修改；開始細化時重新核對已完成的能力。

## Impact

後續會涉及指令、D1 提醒資料、背景排程與 Discord 發送。
排程工具、交付位置及失敗處理尚未決定；不保證 Discord 一定觸發手機通知。

## Non-goals

- 不讓 Agent 未經確認就自動建立或取消提醒。
- 不自動整合外部行事曆、email 或其他通知管道。
- 不以付費服務或持續開機的個人電腦作為既定前提。

## Dependencies

- **必要前置**：`bootstrap-discord-bot`，需要擁有者驗證與 Discord 指令入口。
- **必要前置**：開始開發時需有可持久保存提醒資料、執行排程及發送訊息的方式。
- **建議順序**：第 8 個，可等日記功能穩定後再做；不必先完成 `answer-from-diary`。
- **建議順序**：可參考 `capture-diary-entry` 的 D1 使用方式，但提醒可由擁有者直接建立，不以某筆日記或 Agent 作為必要入口。

## Open Questions

- 時區、時間輸入方式及允許的排程範圍怎麼定？
- 是否包含重複提醒？取消與到期處理重疊時如何表現？
- 提醒送到私人頻道還是私訊？失敗、延遲與重試如何呈現？
- 有哪些符合免費限制的排程方式與額度，是否需要與日記建立關聯？
