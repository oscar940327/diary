# Spec Delta

## MODIFIED Requirements

### Requirement: 指令僅供指定伺服器的擁有者使用

系統 SHALL 只接受指定伺服器內由指定擁有者發出的指令；兩個 ID 都必須符合環境設定，且取自已驗證簽章的互動內容。系統 SHALL 不以名稱、暱稱、角色、管理員權限或額外輸入的帳號參數取代 ID 核對。`/ping` 與 `/record` SHALL 不綁定單一文字頻道。

對可辨識的應用程式指令，若帳號或伺服器不符、缺少可核對的使用者身分，或來自私訊，系統 SHALL 回傳 HTTP 200 與僅操作者可見的拒絕訊息，不執行指令，也不透露允許的 ID。註冊的 `/ping` 與 `/record` SHALL 僅限指定伺服器，不註冊為全域指令。

日記表單送出及「重試顯示」按鈕 SHALL 每次重新套用相同驗證與授權，不能因曾成功開啟表單或帶有 Entry ID 而略過；操作他人或其他環境的紀錄 SHALL 被拒絕，不能讀寫日記或發送頻道訊息。

#### Scenario: 擁有者在兩個文字頻道使用
- **WHEN** 同一擁有者分別在指定伺服器內兩個可使用指令的文字頻道發出簽章有效的 `/ping`
- **THEN** 兩次都通過授權，不因頻道 ID 不同而拒絕

#### Scenario: 其他使用者包含管理員
- **WHEN** 指定伺服器的其他使用者發出簽章有效的指令，即使擁有管理員權限
- **THEN** 系統只向該操作者顯示拒絕訊息，不執行指令

#### Scenario: 擁有者在錯誤伺服器或私訊使用
- **WHEN** 收到擁有者從其他伺服器或私訊發出的簽章有效指令
- **THEN** 系統只向操作者顯示拒絕訊息，不執行指令

#### Scenario: 無法核對操作者
- **WHEN** 已驗證簽章且可辨識為指令，但缺少可核對的操作者帳號 ID
- **THEN** 系統拒絕指令，不預設為擁有者

#### Scenario: 未授權的表單或按鈕
- **WHEN** 非擁有者、錯誤伺服器、私訊或缺少身分的請求送出日記表單或按重試
- **THEN** 私下拒絕，沒有資料庫或頻道副作用，也不透露日記內容

#### Scenario: 有效擁有者嘗試錯誤紀錄
- **WHEN** 通過入口授權，但重試目標不屬於該擁有者及環境
- **THEN** 使用通用私人提示拒絕，不回傳該筆原文或跨環境操作

### Requirement: 私人連通檢查回覆

系統 SHALL 對通過簽章與授權檢查的 `/ping`，在 Discord 規定的 3 秒初次回覆期限內回傳 HTTP 200 與訊息回覆（類型 4），內容為 `Pong!`，並標記為僅操作者可見（`EPHEMERAL`）。`/ping`、拒絕及未支援指令訊息 SHALL 都僅操作者可見，不另發頻道訊息或儲存日記；回覆不得包含憑證或內部錯誤細節。

`/record` 的表單、保存與顯示狀態、重試及失敗提示 SHALL 僅操作者可見；只有經授權且已保存的日記原文可以依日記規格顯示在指定私人日記頻道，不把操作回覆公開到執行指令的頻道。需要外部保存或發送的互動 SHALL 在 3 秒內先確認收到，再更新私人結果，不能阻塞初次回覆等待外部服務完成。

#### Scenario: 正常連通
- **WHEN** 擁有者在指定伺服器執行有效的 `/ping`
- **THEN** 系統在初次回覆期限內回覆 `Pong!`，只有操作者能看見，頻道不新增公開回覆

#### Scenario: 未支援的指令
- **WHEN** 通過驗證與授權的操作者發出此版本未支援的應用程式指令
- **THEN** 系統在初次回覆期限內回覆僅操作者可見的「不支援此指令」提示，不誤回 `Pong!`

#### Scenario: 保存或發送比較慢
- **WHEN** 合法日記表單送出或重試需要等待資料庫或 Discord
- **THEN** 先在初次回覆期限內私人確認收到，之後依實際結果更新，不提前宣稱已保存或已顯示

### Requirement: 無效內容與缺少設定時停止處理

系統 SHALL 對已驗證簽章但無法解析的 JSON、不支援的互動類型、缺少必要互動結構或應用程式 ID 不符的請求回傳 HTTP 400，不執行指令。可辨識的指令缺少操作者或伺服器時，SHALL 依授權拒絕規則處理。

新增支援範圍僅包含日記表單送出與重試按鈕；其已知互動缺少操作者或伺服器時 SHALL 依相同授權拒絕規則處理。未知或無法辨識的表單／按鈕結構 SHALL 回 400，不產生保存或發送副作用；可辨識日記操作的內容、長度或日期不合法則 SHALL 私下說明可修正的原因。

若驗證與授權所需的環境設定缺少或格式無效，系統 SHALL 回傳 HTTP 503，不使用預設擁有者、不略過驗證、不回覆成功。錯誤回應與應用程式日誌 SHALL 不包含 Bot token、互動 token、完整請求本文或內部例外堆疊。

日記專用的資料庫、頻道或發送憑證缺少時 SHALL 停止該操作並提供私人原因與解決方式，不回退到其他環境；這些缺漏 SHALL 不影響共用設定完整時的協定 PING 及 `/ping`。

#### Scenario: 已簽署的錯誤內容
- **WHEN** 設定完整且簽章有效，但本文是無法解析的 JSON、應用程式 ID 不符，或互動結構／類型不支援
- **THEN** 系統回傳 HTTP 400，不回覆指令成功

#### Scenario: 缺少必要設定
- **WHEN** 公開金鑰、應用程式 ID、擁有者 ID 或指定伺服器 ID 缺少或格式無效
- **THEN** 系統回傳 HTTP 503，不放寬限制，回應與日誌不洩漏憑證或原始本文

#### Scenario: 日記設定缺少但連通功能仍可用
- **WHEN** 共用設定有效，但 D1、日記頻道或發送憑證尚未設定
- **THEN** 日記操作回覆私人原因與下一步，協定 PING 及 `/ping` 仍保持原行為

#### Scenario: 未知或畸形表單及按鈕
- **WHEN** 已簽署請求帶未知互動識別、畸形欄位或無法辨識的按鈕資料
- **THEN** 回 HTTP 400，不保存、不發送，也不回傳輸入本文

### Requirement: 測試與正式環境隔離

系統的測試與正式環境 SHALL 使用不同 Discord 應用程式、Worker 與對應設定，不共用 Bot token。更動測試入口或註冊測試指令 SHALL 不修改正式應用程式。本機自動驗收 SHALL 能使用測試用簽署金鑰完成，不依賴 Discord／Cloudflare 真實憑證，也不呼叫其遠端服務。真實憑證 SHALL 不進入版本控制。

日記功能 SHALL 使用不同的測試／正式資料庫及私人日記頻道，測試內容不得混入真實日記。只有發送日記的 Worker 才增加該環境的 Bot token 秘密設定，任何環境缺值 SHALL 不自動沿用另一組。註冊 `/record` SHALL 僅建立／更新該單一 guild command，不整批覆寫，也不移除既有 `/ping`。

#### Scenario: 無雲端憑證的本機驗收
- **WHEN** 開發者在沒有真實 Discord／Cloudflare 憑證的環境執行自動測試
- **THEN** 測試能用測試用金鑰驗證入口、授權與回覆情境，不連線遠端服務或建立資源

#### Scenario: 明確選擇測試環境
- **WHEN** 未來執行測試環境指令註冊或更新測試入口
- **THEN** 操作只使用該環境的應用程式、伺服器與 Worker 設定，正式環境維持原設定

#### Scenario: 註冊操作未指定環境
- **WHEN** 指令註冊操作未明確指定測試或正式環境
- **THEN** 操作停止且不發出註冊請求，不預設操作正式環境

#### Scenario: 測試資料與發送目標隔離
- **WHEN** 在測試環境保存或重試日記
- **THEN** 只寫測試資料庫、發送測試日記頻道，缺少設定就停止，不讀寫正式資料

#### Scenario: 新增記錄指令
- **WHEN** 明確選定環境後註冊 `/record`
- **THEN** 只建立／更新指定 guild 的 `/record`，保留 `/ping` 與其他既有指令
