# Proposal

第 2 個功能 change；2026-11-18 依討論細化規劃，尚未實作。

## Why

讓擁有者能用手機或電腦隨手記錄生活，原文可靠保存後，也能在 Discord 直接閱讀。
這是日記系統第一個真正產生私人紀錄的功能。

## What Changes

- 使用 `/record` 開啟多行表單，內容必填、日期選填，一天可以記錄多筆獨立 Entry。
- 日期不填時歸入送出當下台北時區的今天；允許補寫過去，不接受未來日期，實際建立時間另存。
- 每筆最多 4,000 字元，原文完整存入 D1，再分段顯示到指定私人日記頻道。
- 同一次提交重送不新增 Entry；保存與頻道顯示分開記錄，顯示失敗不回刪原文。
- 成功與失敗的操作回覆僅本人可見；失敗盡量用一句話說明保存狀態、已知原因與解決辦法，原因不明時明說。
- 保存後顯示失敗時提供「重試顯示」按鈕，沿用原 Entry，只補尚未確認成功的部分。
- 測試／正式的 D1 與日記頻道分開，沿用既有兩組 Bot／Worker；增加頻道發訊所需的最小權限。

## Capabilities

### New Capabilities

- `diary-entry-capture`：接收並保存日記原文，回報保存結果，以及顯示到私人頻道。

### Modified Capabilities

- `discord-command-access`：入口增加受授權的表單與按鈕互動，區分私人操作回覆與日記頻道顯示，保留 `/ping`、協定 PING 及既有安全檢查。

## Impact

涉及 HTTP 入口、指令註冊工具、D1 migrations、資料保存、Discord 頻道發訊與操作文件。
日記歸屬日期、實際建立時間與頻道訊息位置分開保存；工程安排見 [design.md](design.md)，分批工作見 [tasks.md](tasks.md)。
技術選擇維持 [技術文件](../../../docs/tech-stack.md)，不新增常駐服務或改用其他平台。

## Non-goals

- 不加入日期瀏覽、搜尋、修改、版本歷史、匯出、Agent 或提醒。
- 不要求 AI 處理才能完成保存。
- 不新增網頁，也不把私人紀錄發布到 note-garden。
- 不做附件輸入、未送出草稿保存、排程自動補送或通用背景任務系統。

## Dependencies

- **必要前置**：已歸檔的 `bootstrap-discord-bot`，重用指令入口、請求驗證與擁有者限制。
- 本機驗收先用本機 D1、測試金鑰及攔截的 Discord HTTP，不依賴真實雲端資源。
- 真實驗收時才依對應授權建立兩組免費 D1、設定兩個私人日記頻道並核對 Bot 權限，不自動升級方案。
- **建議順序**：第 2 個，先能可靠記錄，再增加查閱方式。

## Open Questions

影響本輪功能與 tasks 的操作問題已確認：`/record` 多行表單、選填日期、台北時區、可補寫但不能寫未來、4,000 字元、分段顯示、私人單句錯誤提示及重試按鈕。

真實 D1 名稱／ID、兩個日記頻道 ID 與人工驗收時間留到部署驗收時核對；不在規劃文件放入憑證。
網路逾時可能使個別訊息的送達結果暫時無法確認，必須提示此限制，不承諾跨系統絕對只送一次；規則見 [日記規格](specs/diary-entry-capture/spec.md)。
