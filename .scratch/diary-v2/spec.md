# Diary v2：Discord 指令式 Bot

Status: needs-info

這是新版規劃草稿，尚未完成第一版範圍確認，也還沒有可直接實作的 Tickets。
技術與版本安排已由使用者確認，詳細產品行為依下方待決事項繼續整理。

## 已確認的方向

- 使用 TypeScript、Hono、Cloudflare Workers 與 Cloudflare D1。
- 第一版使用 Discord 指令操作，現階段不製作獨立網頁。
- 手機和電腦都能記錄生活瑣事，滑動閱讀過往內容，也能按日期查閱。
- 維持私人紀錄與 note-garden 公開筆記的區分；不自動把私人內容發布出去。
- 以零付費運作為限制，不使用 Supabase，不自動升級付費方案。
- 保留未來 Agent、提醒及網頁入口的擴充方向；是否納入首版仍待決定。
- 舊版保存在 `v1`；新版從 `main` 的乾淨程式環境開始。技術決定依 [白話技術文件](../../docs/tech-stack.md)。

## 建議的第一條完整流程（待確認）

1. 擁有者使用記錄指令，開啟可輸入多行文字的 Discord 表單。
2. 後端驗證 Discord 請求與擁有者身分，檢查輸入並將原文保存到 D1。
3. 保存完成後，在指定私人日記頻道顯示內容，供手機與電腦連續閱讀。
4. 透過 `/day` 指定日期查詢資料庫，取得當天內容與可用的訊息連結。
5. 頻道訊息顯示失敗時，已保存的日記仍可查到，並提供可恢復的處理方式。

`/record` 是候選名稱，完整指令清單尚未確認。資料庫是原文的保存來源，
Discord 訊息用於顯示；Discord 的訊息順序按發送時間排列，補寫日記不會
插入舊訊息位置，因此日期查詢須依日記的 Entry Time。

## 需要沿用或重新確認的行為

- 一天可以記錄多筆，原文與 AI 衍生內容分開；AI 故障不能造成原文遺失。
- 區分 Entry Time 與系統建立時間；時區與補寫操作需在首版規格中寫清楚。
- Discord 重送請求不能建立重複日記；保存與頻道顯示的重試需分開處理。
- 日記操作須驗證 Discord 簽章並限制擁有者；不能只依賴頻道隱私設定。
- 未來 Agent 的個人經歷回答須可追溯到原文，資料不足時須明說。

以上是設計與驗收的起點，尚非已完成的實作。
