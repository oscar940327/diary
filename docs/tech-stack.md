# Diary 這次決定怎麼做

更新日期：2026-11-09（補回 11 月 4 日的環境決策）。這份文件記下已經決定的技術與原因，之後看這份就能快速接回專案。

## 前端、後端與部署

| 部分 | 這次的選擇 | 白話說明 |
| --- | --- | --- |
| 使用介面（前端） | **Discord** | 手機和電腦都直接用 Discord，先不另外做網頁。 |
| 開發語言 | **TypeScript** | 用來寫 Bot、日記查詢和未來的 Agent 邏輯。 |
| 後端框架 | **Hono** | 接收 Discord 傳來的指令，交給對應功能處理，再回覆結果。 |
| 後端部署 | **Cloudflare Workers** | 把程式放在雲端執行，不用自己的電腦一直開著。 |
| 資料庫 | **Cloudflare D1** | 保存日記原文、日期和之後需要的資料。這次不使用 Supabase。 |

所以目前不用選 Angular、React 等網頁前端框架。Discord 就是第一版的操作介面。
這次也不啟動需要持續連線的 discord.js Client，而是讓 Discord 在使用指令時呼叫後端。

## 平常會怎麼用

先用指令記錄生活，內容存進資料庫，再顯示到自己的日記頻道。
平常可以滑動閱讀，想看某一天時再用 `/day` 查詢。
指令名稱、輸入方式與第一版完整功能，接下來會寫進規格。

## 為什麼這樣選

現在先把「每天能記、之後找得到」做起來，少維護一個網站。
Hono 能配合 Workers，也方便把不同功能整理清楚。
後端與資料庫以免費方案的額度為限制，不自動升級付費。

保留測試與正式兩組環境：測試環境試新功能，正式環境供日常使用。
兩組共用同一個 repo 和私人 Discord 伺服器，Bot、Worker 與憑證各自獨立。
下一個日記保存 change 規劃 D1 與日記頻道時，也將兩組分開，讓測試資料不混入真實日記；目前尚未建立 D1。
Git 保存程式版本，資料與 Discord 訊息的回復需要另外處理，不能只靠程式回退保護日記。

未來增加 Agent、提醒或網頁時，會沿用日記的保存與查詢邏輯，
再增加新的操作入口。這些核心邏輯會和 Discord 的訊息格式分開，
讓功能成長時不必整個重寫。

## 目前還沒決定的事

模型服務與額度用完時的處理方式，需要另外選定。
